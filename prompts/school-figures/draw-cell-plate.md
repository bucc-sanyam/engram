# Prompt — draw an interactive textbook plate

Paste everything below the line into Gemini 3.1 Pro. Change only the **TARGET**
section at the end to name the figure you want.

Reusable across chapters. The reference implementation this was derived from is
`src/lib/cbse/class9/science/figures/ch-02-cell-plate.ts` — worth pasting in as
a worked example if the model's first attempt drifts.

---

You are drawing a labelled biology plate for a class-9 textbook recap app. The
output is a single TypeScript file exporting a `FigureSpec` object. There is no
canvas, no image, no external asset — the drawing IS the path data in the spec,
rendered as SVG.

## Absolute constraint on originality

Draw from the **biology**, not from any existing illustration. Do not trace,
copy, adapt, or "adjust" a published figure, and do not work from a reference
image even if one is supplied to you. A lightly-altered copy of someone's
artwork is a derivative work.

What you may freely use: the anatomy itself (a plant cell has a cellulose wall,
one large vacuole, chloroplasts, a nucleus containing a nucleolus…), the
standard part names, and the general convention of drawing a cell as a labelled
cut-away. Those are facts and conventions. The composition, proportions,
palette and geometry must be generated by your own code.

## The type contract

```ts
type FigureLayer = {
  d: string;                    // SVG path, in viewBox coordinates
  as?: "stroke" | "fill" | "shade" | "light" | "panel";  // default "stroke"
  tint?: string;                // hex; defaults to the parent part's tint
  width?: number;               // stroke width, viewBox units, default 1.2
  opacity?: number;
  dash?: string;                // e.g. "9 7"
};

type FigurePart = {
  id: string;                   // kebab-case, unique in the spec
  label: string;                // ≤ 28 chars — chip text AND leader label
  d: string;                    // outline; several disjoint subpaths allowed
  layers?: FigureLayer[];       // the detail, painted over the body
  tint?: string;                // hex
  labelAt?: [number, number];   // omit to make the part chip-only (no leader)
  leaderAt?: [number, number];  // where the leader touches; defaults to focus centre
  labelAlign?: "start" | "middle" | "end";
  focus: [number, number, number, number];  // REQUIRED [x, y, w, h]
  backdrop?: boolean;           // cytoplasm, cell wall, the slide
  depth?: number;               // paint order, low = behind. default = array index
  blurb: string;                // 25–45 words, plain prose, no markdown
};

type FigureSpec = {
  kind: "figure";
  title: string;                // ≤ 60 chars
  altText: string;              // REQUIRED, ≥ 40 chars: what it shows AND what
                                // interacting does. 2–3 sentences.
  figNumber?: string;           // e.g. "Fig. 2.10 (b)"
  caption?: string;
  viewBox: [number, number];
  parts: FigurePart[];
  scenery?: FigureLayer[];      // non-interactive context, painted before all parts
  magnify?: "camera" | "part";
  maxZoom?: number;
  defaultPartId?: string;
};
```

Import path for the type: `@/lib/sim/types`.

## Path helpers you may import from `@/lib/sim/draw`

`circle(cx, cy, r)` · `ellipse(cx, cy, rx, ry, deg)` · `dots(points, r)` ·
`folds(cx, cy, rx, ry, count, deg, reach)` (cristae reaching in from the edges) ·
`discStack(cx, cy, count, rx, ry, gap)` · `cisterna(cx, cy, halfWidth, bow, thickness)` ·
`tubule(x0, y, x1, wave, thickness)` · `roundRect(x, y, w, h, r)` ·
`stadium(x, y, w, h)` · `spindle(...)` · `chromosomes(...)`

Use them rather than hand-writing arc endpoints. You may also write your own
local geometry functions in the file — that is encouraged, see below.

## How the renderer paints, which determines how you author

Per part, in this order:

1. the body path, flat, in the tint's `fill` tone;
2. **the same path again, offset down-right and clipped to itself, in the
   darker `shade` tone** — this is the built-in roundness crescent, you do not
   author it;
3. your `layers`, in array order;
4. the ink outline, last, so no detail crosses the edge.

`scenery` paints before every part. Outlines use `vector-effect:non-scaling-stroke`.

**Colour: the renderer normalises lightness.** A tint is read for hue and
saturation only — `fill`, `shade`, `ink` and `light` are always emitted at fixed
lightness. So picking a darker hex does **not** produce a darker shape. To make
something recede, **desaturate it**. This is the single most common mistake:
an extruded side face given a vivid dark-green tint comes back *brighter* than
the top face and lights the object from below.

## Making it read as a solid, not a sticker

This is the difference between a plate that looks like a textbook illustration
and one that looks like flat boxes. A flat head-on plan view is the failure
mode. Build a pseudo-3-D cut-away instead:

1. **Project.** Write a `plan(radius, dy)` helper that places points on a
   polygon and multiplies every y by a `SQUASH` factor (~0.6). Now the shape is
   a floor being looked down at, not a wall being faced.
2. **Round the corners.** A hard vertex reads as a diagram of a box. Write a
   `roundedPoly(points, r)` that replaces each corner with a quadratic.
3. **Extrude.** Give the outer boundary a visible near side: take only the
   **front-facing edges** of the top outline and extrude them straight down by
   ~26 units, as one `scenery` fill plus a thin stroke. Do **not** offset the
   whole silhouette downward — on a wide shape that exposes the lower-left and
   lower-right diagonals too, and the result reads as a puddle of colour pooled
   around the object.
4. **Two interior planes.** Put the floor `LIP` (~24) below the top rim. The
   band of the rim that the floor does not cover becomes the visible cut edge of
   the wall at the back. Paint it as a pale `light` layer.
5. **Cut the hole at the FLOOR outline, not the rim.** If the containing ring's
   hole is the rim outline, the floor — which sits `LIP` lower — hangs out past
   the bottom of the thing it is supposed to be sitting inside.
6. **No plain ellipses for organelles.** Write a `blob(cx, cy, rx, ry, wobble[])`
   that runs a smooth closed curve (Catmull-Rom → cubic) through points whose
   radius is modulated per-point, e.g. `[1, 0.95, 1.04, 0.97, 1.02, 0.94]`.
7. **Give each organelle a highlight.** A small pale `light` ellipse up and left
   of centre, ~0.44×0.30 of its radii.
8. **Interior detail earns the look**: grana dots in chloroplasts, `folds()` for
   cristae, ribosome specks studding the ER, a tonoplast stroke inset inside the
   vacuole, a dashed inner line in the wall for cellulose layering.

## The interaction: `magnify: "part"`

Set `magnify: "part"`. Clicking a part lifts **that part** out — it scales about
its own `focus` centre, drifts toward the middle, casts a shadow, and the rest of
the specimen stays in place, dimmed, as context.

Consequences for how you author `focus`:

- **`focus` must tightly bound ONE representative shape**, not the bounding box
  of every copy. A lifted part is clipped to its focus box (padded 35%), so if a
  part is four scattered chloroplasts sharing one path, the focus box picks which
  single chloroplast the reader gets to inspect. A loose box shows debris.
- Scale is `clamp(min(viewW, viewH) * 0.30 / max(focusW, focusH), 1.35, 2.8)`.
  A focus box far larger than the shape gives a limp 1.35× lift.
- `backdrop: true` parts light up but never scale. Mark the cytoplasm, the cell
  wall and any container that way — the container *is* the plate.
- **A sub-part must also be a layer of its parent.** The nucleolus is its own
  clickable part AND a `shade` layer inside the nucleus, or the nucleus lifts
  away and leaves its nucleolus hanging in the cytoplasm. Define the shape once
  in a `const` and use it twice.

## Labels

- Text is 15px in viewBox units, wrapped at 15 characters, 17px line height.
- Left-side labels sit at a common x with `align: "end"`; right-side at a common
  x with `align: "start"`. Leave ~150 units of margin each side for them.
- Every label must fit inside the viewBox and must not overlap another label.
- `leaderAt` should touch the actual structure. Author it whenever the focus
  centre would land on empty space.
- Parts that would crowd the plate (ribosomes, a nucleolus) can omit `labelAt`
  and be reachable from the chip row only.
- Keep the viewBox tight to the content. Dead vertical space above the drawing
  is the usual sloppiness — measure where your topmost label and bottommost
  element actually sit.

## Palette

One `tint` per part, chosen for hue and saturation (see the colour note above).
Aim for a saturated, friendly, textbook register — greens for wall and
chloroplasts, cyan for the vacuole, purple for the nucleus with a deeper purple
nucleolus, warm orange for mitochondria, blue for ER, pink for Golgi. Collect
them in a `const T = { … }` at the top of the file.

## Prose

Every `blurb` is 25–45 words, plain prose, no markdown, written for a 14-year-old:
what the part is and what it does, and where useful how it differs from the
equivalent in the other cell type. Do not pad. `altText` describes the whole
plate and states that selecting a part lifts it out enlarged.

## Output

One TypeScript file. Local geometry helpers at the top, then the palette, then
the exported `FigureSpec`. Comment the non-obvious geometry — especially the
projection constants — explaining *why*, not what. No `any`. No new dependencies.
No `Math.random` (the spec must be deterministic).

## Verification the author must be able to pass

```
npx tsc --noEmit
npx tsx scripts/render-figures.mts   # paints every plate to .figures/ and audits
                                     # labels running off the plate, overlapping
                                     # labels, focus boxes outside the viewBox,
                                     # duplicate ids
npx tsx scripts/validate-cbse.mts
```

Then rasterise and actually look at it:
`qlmanage -t -s 1100 -o png .figures/*.svg`

Expect to iterate two or three times on the render. Nothing here is judgeable
from the source.
